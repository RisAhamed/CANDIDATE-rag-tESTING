INTERVIEWER: How do you handle database migrations in a microservices environment?

[00:13:15]
CANDIDATE: Each service owns its database - we don't share databases between services. We use Alembic for SQLAlchemy migrations. Migrations run as Kubernetes Jobs before the new service version is deployed. We follow expand-contract pattern for backward-compatible changes. For rollbacks, we keep the previous version running until the new version is verified healthy.

[00:15:00]
INTERVIEWER: What's your approach to API versioning?

[00:15:15]
CANDIDATE: We use URL-based versioning (v1, v2) for breaking changes. For backward-compatible changes, we don't version - we just add new fields. We maintain deprecation policies where old versions are supported for 6 months with clear sunset headers. We use FastAPI's dependency injection to handle version-specific logic cleanly.

[00:17:15]
